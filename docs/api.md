# REST API Reference — Personal Sports Digital Twin

Base URL: `http://localhost:8000/api/v1`

All protected endpoints require an `Authorization: Bearer <JWT_TOKEN>` header.

## 1. Authentication (`/auth`)

### `POST /auth/register`
Creates a new user account and associated default athlete profile.
- **Request Body**:
  ```json
  {
    "email": "athlete@example.com",
    "password": "SecurePassword123!",
    "display_name": "Alex Runner",
    "sport": "running",
    "experience_level": "intermediate"
  }
  ```
- **Response**: `201 Created`
  ```json
  {
    "access_token": "ey...",
    "token_type": "bearer",
    "user": { "id": "...", "email": "athlete@example.com" },
    "athlete": { "id": "...", "display_name": "Alex Runner", "sport": "running" }
  }
  ```

### `POST /auth/login`
Authenticates with email and password.
- **Request Body**:
  ```json
  {
    "email": "athlete@example.com",
    "password": "SecurePassword123!"
  }
  ```
- **Response**: `200 OK` (returns `access_token` and athlete profile).

---

## 2. Athlete Profile (`/athletes`)

### `GET /athletes/me`
Retrieves current authenticated athlete's profile.

### `PUT /athletes/me`
Updates profile information (sport, experience level, physical parameters).

---

## 3. Movement Sessions & Processing (`/sessions`)

### `POST /sessions/upload`
Uploads a recorded movement video file (multipart/form-data).
- **Form Fields**: `file` (MP4/MOV/AVI video), `recorded_at` (ISO timestamp, optional).
- **Validation**: File extension, MIME type, size limit ($\le 100\text{ MB}$), duration ($2\text{s} - 300\text{s}$).
- **Response**: `201 Created` (returns session with `processing_status: "PENDING"`).

### `POST /sessions/{session_id}/process`
Triggers OpenCV + BlazePose processing, metric extraction, baseline updates, anomaly checks, and twin state snapshot generation.
- **Response**: `200 OK` (returns computed metrics, quality score, deviations, and updated twin state).

### `GET /sessions`
Lists chronological sessions for the current athlete (paginated).

### `GET /sessions/{session_id}`
Retrieves session details, per-frame summary pose metrics, cadence, and data quality indicators.

---

## 4. Digital Twin & Longitudinal Analytics (`/twin`, `/trends`, `/anomalies`)

### `GET /twin`
Returns the active, authoritative Digital Twin state for the authenticated athlete:
- `state_version` (integer)
- `current_metrics` (latest session values)
- `personal_baselines` (longitudinal baseline distributions)
- `metric_trends` (slopes and directions)
- `active_deviations` (statistical anomalies detected in recent sessions)
- `data_quality_index` (average landmark tracking confidence)

### `GET /twin/history`
Returns historical snapshot versions of the Digital Twin for longitudinal auditing.

### `GET /metrics/history/{metric_name}`
Returns time-series datapoints for a specific metric across all athlete sessions, formatted for graphing with baseline bands.

### `GET /trends`
Returns trend analysis for all tracked metrics (`IMPROVING`, `STABLE`, `DECLINING`).

### `GET /anomalies`
Returns detected deviations across athlete sessions with severity ratings.

---

## 5. Insights & Grounded Recommendations (`/recommendations`)

### `GET /recommendations`
Returns grounded athletic recommendations and natural-language explanations generated by Gemini API (or the deterministic fallback engine).

---

## 6. Demo / Simulated Data (`/demo`)

### `POST /demo/seed`
Seeds a verified, auditable 5-session progression for demonstration purposes. All created records have `is_demo_data: true`.
